# AI generated OpenJSCAD designs

## Overview

This repository contains OpenJSCAD-based design experiments and printable parts, plus designs built in [SolidCraft](#working-with-solidcraft).  
Each design lives in its own folder under [`designs/`](./designs/) with source and generated artifacts.

## Design Summary

- [**Bell hammer**](./designs/bell-hammer/): replacement hammer for a Brompton bike bell with offset pocket, side bore, and stepped top.
- [**Boxmaker**](./designs/boxmaker/): set of open-top box and cylinder variants generated from measured figure dimensions.
- [**Foamcutter v2**](./designs/foamcutter-v2/): updated foam cutter support assembly plus X-Acto No. 11 outline tooling model.
- [**Staircase with landing**](./designs/starcase-with-landing/): parametric U-turn staircase model with landing and glue tabs.
- [**Mounting hook**](./designs/mounting-hook/): 48 mm hook-profile part from sketch, extruded 20 mm.
- [**Totemikk**](./designs/totemikk/): parts for an LED totem — ring/partition shell segments, an internal ring+beam skeleton with a coupler, a push-fit bottom plug/foot, a 4-key keypad, a gear ring, a mic holder, a bottom support, and a wall-mount hook.
- [**Adapter — BnD mount to tube**](./designs/adapter-BnD-mount/): matches a BnD 20Vmax tool mount's 60x65mm/3-hole back plate on one side, half-shell tube clamp (Ø51mm) with bolted end flanges on the other; 2 pieces sandwich the tube.
- [**Insta360 tripod leg (sliding slot)**](./designs/insta360-tripod-leg/): variation on the Insta360 tripod mount's leg — flat tapered blade with a rounded hub-end knuckle, but the pivot hole is replaced by a lengthwise slot so the leg can pivot and slide up along the pole once folded. Proposal for a single leg; the central hub is not modeled yet.
- [**Acid badge**](./designs/acid-badge/): circular band with 24 evenly-spaced 3mm holes, 5mm apart center-to-center.
- [**Bluetooth adapter box**](./designs/bluetooth-adapter-box/): small box with 46x21x8mm inner space, 1.5mm walls, a 10x4mm hole in one short wall, a 6mm round hole in a long wall and a separate push-fit lid with a slotted round grille.
- [**TD-3-MO**](./designs/td3-mo/) (SolidCraft): look-alike model of a Behringer TD-3-MO bass line synth — bevelled knobs and bar-type selector knobs, jacks, buttons, switches, LEDs, panel fields, lines and labels. [Open in SolidCraft](https://solidcraft.io/app?open=https%3A%2F%2Fraw.githubusercontent.com%2Fsponnet%2Fai-3d-designs%2Frefs%2Fheads%2Fmain%2Fdesigns%2Ftd3-mo%2Ftd3-mo.sc)

## Working with SolidCraft

[SolidCraft](https://solidcraft.io) is a parametric 3D CAD app (desktop and browser) that AI assistants can drive over MCP. Designs are `.sc` files that keep their full history (sketches, features, parameters), so they stay editable.

### Open a design from this repo

Every SolidCraft design here has an **Open in SolidCraft** link. It loads the `.sc` file from GitHub into the browser app as an unsaved copy:

```
https://solidcraft.io/app?open=<URL-encoded HTTPS link to the .sc file>
```

- Use the raw file URL, e.g. `https://raw.githubusercontent.com/sponnet/ai-3d-designs/refs/heads/main/designs/td3-mo/td3-mo.sc`, and encode it with `encodeURIComponent`. `raw.githubusercontent.com` allows CORS from any origin, which the app requires.
- To try a design from another branch, replace `refs/heads/main` with that branch.
- Add `&embed` for a viewer without menus (for an `<iframe>`), `?webgl` if WebGPU does not work in your browser.
- On the desktop app, open the file with **File > Open** or `open designs/td3-mo/td3-mo.sc`.

### Set up the MCP server

Install SolidCraft (the desktop app ships `solidcraft-cli`; Homebrew puts it on the `PATH`), then register the MCP server for every project:

```bash
claude mcp add -s user solidcraft -- solidcraft-cli mcp
```

- `solidcraft-cli mcp` runs headless; `solidcraft-cli mcp --connect 127.0.0.1:<port>` drives the open app window so you watch the model being built. `solidcraft-cli mcp setup --live` adds a `solidcraft-live` server for that.
- The app's control port was `27878` here (not the `7878` that `mcp setup --live` wrote); check with `lsof -nP -iTCP -sTCP:LISTEN | grep -i solidcraf`.
- MCP servers added during a Claude session only load in a new session. Until then, [`tools/solidcraft-call.py`](./tools/solidcraft-call.py) runs MCP tool calls against the running app from a JSON file: `python3 tools/solidcraft-call.py calls.json`.
- The server only reads and writes files in its own folders and those passed with `--allow-path` (the helper script allows the repository root), so `save` and `screenshot {path}` can write straight into `designs/`.

### Modelling tips

- Read `skill_reference {"skill": "solidcraft-modeling"}` first: it lists sketch planes, entity ids, dimension roles and the feature traps. Never call `list_commands` without a `filter`, its reply is over 100 KB.
- Put several steps in one `batch`; a failing step rolls the whole batch back, so keep risky steps in batches of their own.
- Primitives (`solid.box`, `solid.cylinder`, `solid.cone`, `solid.sphere`, `solid.torus`) take expressions over parameters for sizes and positions; that is the quickest way to a parametric part. A sketch profile with `solid.extrude` (`operation: cut`, `targets: [body]`) cuts any shape out of one body, also at an angle via a sketch plane `{origin, x_dir, y_dir}`.
- Parameter names must not clash with expression functions (`floor` is refused).
- Fonts for `sketch.text` are given by installed name (`"DIN Alternate Bold"`, `"Helvetica"`); a font file path is outside the server's allowed folders.
- Check every step with `measure` against a hand-computed volume and with `screenshot {"source": "model", "view": "iso"}`.

### Known limits

- **Booleans on many bodies can hang the app.** Combining ~400 text letters into one body with `solid.combine` never finished and the app had to be restarted. Keep many small parts as separate bodies and group them with `browser.group` instead.
- **Parameter changes on designs with many booleans can crash the app** (seen once while changing a bucket's handle diameter). Save or export a script (`timeline.export_script`) before flexing parameters.
- **Renders are capped at 262,144 triangles.** `render.preflight` reports `admission.triangles` and `render.scene` the triangles per body. A `solid.torus` is about 9,000 triangles; a cylinder is a few hundred. The render error only says *LimitExceeded … triangle/appearance/polyline admission cap*.
- Sketch text becomes one body per letter, even with `operation: new`.
- `timeline.redefine` keeps the feature type; to swap a torus for a cylinder, delete the feature and add a new one with the same `name`/`body_name`.
